# BORISTENE ETS — Content Studio

Це оновлення розширює **поточний Django-проєкт**, не замінюючи його на іншу CMS і не змінюючи візуальну структуру публічних сторінок. Для інтерфейсу використовується **django-jazzmin 3.0.5** (Django 4.2+).

## Що можна редагувати

1. **Page texts** — тексти й підписи у Django-шаблонах на всіх сторінках. Фільтри `Page` і `Section`, пошук. Кожне поле відображається у відповідному місці на сайті. HTML у текстах екранується, щоб не додати шкідливий код.
2. **Page images** — зображення, що підключаються як статичні ресурси шаблонів, включно з фоновим фото в Hero. Можна завантажити новий файл або вказати URL. Динамічні фото проектів/галерей редагуються у власних моделях.
3. **Page links** — зовнішні посилання, соціальні мережі, `mailto:` та `tel:` (основні контакти централізовано в Association details).
4. **Association and banking details** — єдиний запис для IBAN, SWIFT/BIC, отримувача, банку, Codice Fiscale, юридичної адреси, електронної пошти і телефону. Реквізити відображаються одразу після збереження. Перевіряйте платіжні реквізити перед публікацією.
5. **Donation / membership levels** — шість стартових рівнів зі збереженням їх цін і переваг; можна додати нові, змінювати порядок і видимість.
6. **Усі наявні моделі** — Projects, Events, Team, Partners, Media, FAQ, Achievements, Activities, Festival Editions, Book Club Meetings, photos, Project Supporters, Partner Credits (зокрема через окремі редактори).

Тексти, які генеруються програмно (наприклад, дати/лічильники, серверні повідомлення, логіка реєстрації, повідомлення в JS), не стали окремими записами CMS. Для зручності редактора — кожен HTML-текст отримав окреме поле; деякі повтори заголовків потрібно редагувати окремо (наприклад, desktop/mobile навігація).

## Встановлення

Безпечний рекомендований спосіб — скористатися `install_cms.sh` у корені ZIP. Інсталятор працює зі звичайним локальним `~/k/brsfn`, не чіпає `media`, `.env`, `venv`, `db*.sqlite3`, робить резервну копію змінюваних файлів і активної SQLite БД. Перед встановленням `django-jazzmin` потрібен доступ до PyPI.

```bash
bash <(unzip -p "$HOME/Downloads/brsfn_cms_complete.zip" install_cms.sh) "$HOME/Downloads/brsfn_cms_complete.zip" "$HOME/k/brsfn"
```

Залежно від назви папки завантаження замініть `$HOME/Downloads` або передайте абсолютний шлях до ZIP. Якщо у вас є незбережені локальні зміни цих шаблонів, врахуйте, що інсталятор замінить їх, але перед цим збереже копії.

Якщо хочете налаштувати вручну, встановіть `django-jazzmin==3.0.5` у **наявному venv**, скопіюйте файли з ZIP без папок `media`, `venv` і баз даних, потім виконайте:

```bash
cd ~/k/brsfn
source venv/bin/activate
python manage.py check
python manage.py migrate
python manage.py sync_site_content
python manage.py createsuperuser  # тільки якщо ще немає адміністратора
python manage.py runserver 127.0.0.1:4455
```

Адреса: **http://127.0.0.1:4455/admin/**. Користувач мусить мати права `is_staff`, а для редагування всіх моделей — `is_superuser` або відповідні granular permissions.

### SQLite

Поточний `core/settings.py` до оновлення використовував `db1.sqlite3`; щоб **не загубити старих користувачів і записи**, він **залишається типовою базою незалежно від наявності іншого файлу**. Для використання `db.sqlite3` потрібно явно вказати змінну середовища `BORISTENE_DB_FILE=db.sqlite3`. Можна встановити `BORISTENE_DB_FILE` як шлях до конкретної бази (відносно кореня проекту або абсолютний):

```bash
export BORISTENE_DB_FILE=db1.sqlite3
```

**Не створюйте пустий `db.sqlite3`, якщо робочі дані містяться у `db1.sqlite3`.** Для переходу на назву `db.sqlite3` скопіюйте поточну базу через SQLite Backup API після зупинки сервера. Дані під час встановлення не імпортуються з `db23.sqlite3` чи `dbNEW23.sqlite3` автоматично.

### Перевірки

Після встановлення рекомендовано:

```bash
python manage.py check
python manage.py showmigrations landing
python manage.py test landing.tests_cms
python manage.py runserver 127.0.0.1:4455
```

Для кожної сторінки перевірте редакторський сценарій: змініть короткий заголовок у `Page texts`, оновіть сторінку, поверніть значення. Для зображень потрібен `MEDIA_ROOT`, а на продакшені — правильна роздача `/media/` і `/static/`.

## Додатково

- Каталог стартового контенту `landing/cms_defaults.json` та міграція `0007_site_content_studio.py` створюють записи лише за відсутності. Наступні `migrate` або `sync_site_content` **не перезапишуть** ваші редакторські зміни.
- URL-адреси й моделі старого сайту лишилися без змін; додані тільки нові таблиці.
- Якщо на головній сторінці є декілька окремих однакових фраз (мобільна/настільна навігація), для них можуть бути окремі поля.
- Бібліотека Jazzmin встановлюється окремо командою `pip install django-jazzmin==3.0.5`; вона **не входить у вихідний ZIP** і не змінює версію Python.
- Для production обов’язково установіть `DEBUG=False`, надійний `SECRET_KEY`, список `ALLOWED_HOSTS`, HTTPS, backups, а також обмежте доступ до /admin. Поточний DEBUG/SECRET_KEY у вихідному проєкті демонстраційні; їх не змінено без окремої конфігурації деплойменту.
