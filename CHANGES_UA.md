## Розгортання на Ubuntu / Linux (спершу на копії!)

**ПРАЦЮЮЧУ БАЗУ НЕ ПЕРЕЗАПИСУВАТИ.** В архіві збережено її вихідний стан, але якщо після архівування на продакшні були нові записи, обов'язково використовуйте актуальну базу продакшна. Не виконуйте `flush`, `reset_db`, `rm db1.sqlite3` або інші руйнівні команди.

Зайти в корінь розпакованого проєкту (де лежить `manage.py`):

```bash
# Якщо віртуальне середовище вже створене:
source venv/bin/activate
# Або створити нове, якщо venv відсутнє в архіві:
# python3 -m venv venv && source venv/bin/activate

pip install -r requirements.txt

# Резервна копія АКТУАЛЬНОЇ активної БД перед міграцією
cp -p db1.sqlite3 "db1.before_editorial_$(date +%Y%m%d_%H%M%S).sqlite3"

python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py migrate --plan
python manage.py migrate
python manage.py test landing
python manage.py runserver
```

Перевірити сторінки `/`, `/projects/`, `/projects/unbreakable-ukraine/`, `/support/` та Django Admin. Для нових подій, випусків фестивалю і зустрічей спочатку потрібно створити відповідні записи через адмінку.

**Технічна примітка:** у середовищі збірки Django встановити не вдалося (немає доступу до пакункового репозиторію); тому тут виконані лише синтаксичні / структурні / checksum перевірки, але не живий `manage.py check`, `migrate` чи `test`. Їх потрібно обов'язково виконати до розгортання.

**Безпека:** поточний проєкт із вихідного архіву має `DEBUG=True`, `ALLOWED_HOSTS=['*']` і `SECRET_KEY`, прописаний у `core/settings.py`. Перед публікацією в інтернеті потрібно налаштувати production-параметри й перенести секрети в змінні середовища. Не змінювали тут `SECRET_KEY`, щоб випадково не завершити чинні сесії й не зламати робочу конфігурацію.
